react-native-filament wraps Google's [Filament](https://google.github.io/filament) renderer as [Nitro Modules](https://nitro.margelo.com) HybridObjects. The React components are a thin layer that creates and configures them.

## Objects

```txt
Filament (FilamentFactory)
└── Engine ─────────────── render thread, render loop, managers
    ├── ViewTarget ─────── one FilamentView's surface, View options, picking, snapshots
    ├── Recorder ───────── offscreen MP4 rendering
    ├── Scene, Camera, Light, Skybox, IndirectLight, Renderable
    ├── Model ──────────── a glTF asset and its instances
    │   └── ModelInstance → Animator, AnimationPlayer
    ├── Material → MaterialInstance
    ├── Texture
    ├── TransformBinding, ValueBinding, CameraManipulator
    └── PhysicsWorld → CollisionShape, RigidBody
```

- [`Filament`](/api/functions/filament) creates Engines and lists the backends the device supports.
- [`Engine`](/api/hybrid-objects/engine) owns a Filament engine and its render thread. It creates every other object, and destroys them when it shuts down.
- [`NativeFilamentView`](/api/components/native-filament-view) is a Nitro HybridView. A [`ViewTarget`](/api/hybrid-objects/view-target) renders into its surface.
- [`TransformManager`](/api/hybrid-objects/transform-manager), [`RenderableManager`](/api/hybrid-objects/renderable-manager) and [`LightManager`](/api/hybrid-objects/light-manager) read and write the components of entities. An entity is a number.

Each component creates or configures one of these objects:

| Component | Native object |
|---|---|
| `FilamentScene` | An `Engine` from `Filament.createEngine()`, or the one passed as `engine`, plus a `Scene` and a `Camera` |
| `FilamentView` | A `NativeFilamentView` and a `ViewTarget` from `engine.createViewTarget()` |
| `Camera` | The scene's `Camera` |
| `Model` | A `Model` from `engine.loadModel()`, added with `scene.addModel()` |
| `Animator` | An `AnimationPlayer` from `instance.animator.createPlayer()` |
| `Light` | A `Light` from `engine.createDirectionalLight()` and the other `create*Light()` methods |
| `EnvironmentalLight` | An `IndirectLight` from `engine.loadIndirectLight()` |
| `Skybox` | A `Skybox` from `engine.loadSkybox()` or `engine.createSkybox()` |

Inside a `FilamentScene`, [`useFilamentContext()`](/api/hooks/use-filament-context) returns the objects it created, so you can mix imperative code into a declarative scene. `view` and `target` are set inside a `FilamentView`.

```tsx
import { useFilamentContext } from 'react-native-filament'

function Inspector() {
  const { engine, scene, camera, transformManager, renderableManager, lightManager, view, target, workletContext } = useFilamentContext()
  return null
}
```

## Lifetime

The Engine drives rendering natively. A `CADisplayLink` on iOS and a `Choreographer` on Android wake the render thread only while something needs a frame, so no JS runs per frame unless you register a frame callback.

### Disposing

`dispose()` marks an object and everything it owns as disposed right away and destroys them on the render thread. It works from any thread, and calling it again does nothing. Calls that reach a disposed object's native state throw an error starting with `FilamentDisposedError`, also through other references. Values captured at creation, such as `entity` and `boundingBox`, stay readable.

- Disposing an owner disposes what it owns: a physics world's bodies and shapes, a material's instances, everything under the Engine.
- Disposing a light, renderable, model, skybox or indirect light removes it from every scene that shows it.
- Transform bindings, camera manipulators and animation players stop when disposed. Setters of a disposed `TransformBinding` are ignored. A `ValueBinding` holds no native state, so disposing it changes nothing.

`engine.shutdown()` disposes everything the Engine created, stops its render thread and resolves once that has finished. Call it from the React Native runtime or Reanimated's UI runtime. A `FilamentScene` without an `engine` prop shuts its Engine down on unmount; `useEngine()` does the same.

```tsx
import { ModelRenderer, useModel } from 'react-native-filament'

function Drone() {
  const model = useModel(require('./drone.glb'))
  return <ModelRenderer model={model} />
}
```

</Declarative>
<Imperative>

```tsx
const model = await engine.loadModel({ uri }, {})
const player = model.getInstance(0).animator.createPlayer()

model.dispose()

await engine.shutdown()
```

</Imperative>

Components and hooks dispose what they create when they unmount or their inputs change. In the imperative example, disposing the model also stops `player`, and `engine.shutdown()` destroys whatever is left.

### Keep references to what you create

Objects stay alive only while JavaScript or another native object references them. When the garbage collector releases the last reference:

- a `Light` or `Renderable` is destroyed, even though the scene still stores its entity number;
- a `ViewTarget` stops rendering, a `TransformBinding` stops applying values, an `AnimationPlayer` stops playing and a `CameraManipulator` stops moving its cameras;
- an Engine shuts down once nothing references it or any object it created.

Native objects keep their dependencies alive: a scene keeps its models, skybox and indirect light, a view target and recorder keep their scene and camera, a rigid body keeps its world and shape, a renderable keeps its material instance, and a material instance keeps its textures. A physics world and its bodies keep each other alive, so dispose the world yourself.

Keep what you create in a variable, a ref, state or the result of your effect until you dispose it. Components and hooks do this for you.

### Creating your own resources

`useDisposableResource(create, deps)` is what the built-in components use. It calls `create` when `deps` change and returns the object once it exists, or `undefined`. It disposes the object when `deps` change again or the component unmounts, including an object whose creation finishes later, and throws a failed creation to the closest error boundary. `create` may return the object, a Promise of it, or `undefined` to create nothing. `useEntityInScene(scene, entity)` adds an entity to the scene while the component is mounted.

```tsx
import { Image } from 'react-native'
import { useDisposableResource, useFilamentContext } from 'react-native-filament'

const shadowMaterial = Image.resolveAssetSource(require('./transparent_shadow_material.filamat'))!

function useShadowMaterial() {
  const { engine } = useFilamentContext()
  return useDisposableResource(() => engine.loadMaterial({ uri: shadowMaterial.uri }), [engine])
}
```

All components and hooks are safe under React StrictMode: `useDisposableResource` starts creating after the commit's effects have run, so an effect that StrictMode cleans up right away creates nothing, and a creation already running is disposed when it finishes. Do the same in your own effects: dispose in the cleanup what the effect created, dispose an asynchronous result that arrives after the cleanup, and remove frame listeners, collision listeners and SharedValue bindings in the cleanup. [Debugging](/docs/debugging#counting-live-resources) shows how to find what was not disposed.
