Each `FilamentScene` has one camera, and every `FilamentView` of the scene renders through it. The [`<Camera>`](/api/components/camera) component configures its lens and pose. Imperatively, a [`Camera`](/api/hybrid-objects/camera) comes from `engine.createCamera()` and renders through the targets you pass it to with `target.setCamera()`.

## Pose and lens

| `<Camera>` prop | Default |
|---|---|
| `cameraPosition`, `cameraTarget`, `cameraUp` | `[0, 0, 8]`, `[0, 0, 0]`, `[0, 1, 0]`, applied with `camera.lookAt(eye, center, up)` |
| `focalLengthInMillimeters` | `28` |
| `near`, `far` | `0.1`, `100` |
| `aspect` | the aspect ratio of the closest `FilamentView` |

The lens props are applied with `camera.setLensProjection(focalLengthMm, aspect, near, far)`.

```tsx
import { Camera, FilamentView } from 'react-native-filament'

    <FilamentView style={{ flex: 1 }}>

    </FilamentView>
  )
}
```

```tsx
import { runOnRenderThread } from 'react-native-filament'

const camera = await runOnRenderThread(engine, () => {

})
```

</Imperative>

The camera methods run on the render thread. `target.addOnResizeListener()` calls its listener with the drawable size in pixels, and once right away if the target already has a surface. Set `aspect` when there is no view to take it from, for example for a [`useRecorder`](/api/hooks/use-recorder) video.

![The camera's view frustum between the near and far planes](/img/camera-projection.png)

`near` is the closest distance at which objects are rendered. `far` is used for culling and shadow calculations; Filament renders with the far plane at infinity, so geometry that crosses it is not clipped. Keep the ratio of `near` to `far` between about 1:100 and 1:100000, as Filament's `Camera.h` advises.

### Animating the pose

Each pose prop also accepts a Reanimated `SharedValue<Float3>`, which moves the camera without React renders. Imperatively, write the camera entity's transform through a [`TransformBinding`](/api/hybrid-objects/transform-binding), with [`lookAtRotation`](/api/functions/look-at-rotation) for the rotation.

```tsx
import { useEffect } from 'react'
import { Easing, useDerivedValue, useSharedValue, withRepeat, withTiming } from 'react-native-reanimated'
import { Camera, type Float3 } from 'react-native-filament'

function OrbitingCamera() {
  const angle = useSharedValue(0)
  useEffect(() => {
    angle.value = withRepeat(withTiming(2 * Math.PI, { duration: 8000, easing: Easing.linear }), -1)
  }, [angle])
  const position = useDerivedValue<Float3>(() => [Math.sin(angle.value) * 8, 1, Math.cos(angle.value) * 8])
  return <Camera cameraPosition={position} />
}
```

### Other projections and exposure

The native camera also has `setProjection(fovDegrees, aspect, near, far)`, `setOrthographicProjection(left, right, bottom, top, near, far)` and `setExposure(aperture, shutterSpeedSeconds, sensitivityIso)`. The default exposure is f/16, 1/125 s, ISO 100. In a `FilamentScene`, get the scene's camera from `useFilamentContext()` and call them on the render thread. `<Camera>` sets a perspective lens projection whenever its view resizes or its lens props change, so for an orthographic projection leave `<Camera>` out and set the projection and pose of `useFilamentContext().camera` yourself.

In `on-demand` [render mode](/docs/rendering#render-modes), camera changes made on the render thread, including plain-value `<Camera>` props, show up with the next frame something else requests; call `engine.requestFrame()` after them.

## Orbiting with gestures

![Orbiting the camera around a model with one finger](/img/demo-camera-pan.gif)

A [`CameraManipulator`](/api/hybrid-objects/camera-manipulator) turns input into orbiting, panning and zooming, and a camera can follow it. Gestures queue commands from the UI runtime and the render thread applies them at the start of each frame, with no JS per frame. [`useOrbitGestures(manipulator)`](/api/hooks/use-orbit-gestures) builds the [Gesture Handler](https://docs.swmansion.com/react-native-gesture-handler) gesture (a one-finger pan orbits, a pinch zooms and a double tap returns home) and needs `react-native-gesture-handler`.

`useCameraManipulator(options)` creates the manipulator with `engine.createOrbitManipulator()` and disposes it on unmount. Passing it to `<Camera cameraManipulator>` makes the camera follow it instead of the pose props and sizes its viewport to the view in points. Imperatively, call `camera.followManipulator(manipulator)` on the render thread and `manipulator.setViewport(width, height)` with the view's size in points.

<ApiTabs>
<Declarative>

```tsx
import { GestureDetector } from 'react-native-gesture-handler'
import { Camera, FilamentScene, FilamentView, useCameraManipulator, useOrbitGestures, type CameraManipulator } from 'react-native-filament'

function OrbitView({ manipulator }: { manipulator: CameraManipulator }) {
  const gesture = useOrbitGestures(manipulator)
  return (
    <GestureDetector gesture={gesture}>
      <FilamentView style={{ flex: 1 }}>
        <Camera cameraManipulator={manipulator} />
      </FilamentView>
    </GestureDetector>
  )
}

function Orbit() {
  const manipulator = useCameraManipulator({ homePosition: [0, 0, 8], orbitSpeed: 0.003 })
  return manipulator == null ? null : <OrbitView manipulator={manipulator} />
}

export function App() {
  return (
    <FilamentScene>
      <Orbit />
    </FilamentScene>
  )
}
```

</Declarative>
<Imperative>

```tsx
import { View } from 'react-native'
import { GestureDetector } from 'react-native-gesture-handler'
import { NativeFilamentView, runOnRenderThread, useOrbitGestures, type FilamentView } from 'react-native-filament'

const manipulator = engine.createOrbitManipulator({ homePosition: [0, 0, 8], orbitSpeed: 0.003 })

await runOnRenderThread(engine, () => {
  'worklet'
  camera.followManipulator(manipulator)
})

function OrbitView({ onView }: { onView: (view: FilamentView) => void }) {
  const gesture = useOrbitGestures(manipulator)
  return (
    <GestureDetector gesture={gesture}>
      <View
        style={{ flex: 1 }}
        onLayout={({ nativeEvent }) => manipulator.setViewport(nativeEvent.layout.width, nativeEvent.layout.height)}
      >
        <NativeFilamentView style={{ flex: 1 }} hybridRef={onView} />
      </View>
    </GestureDetector>
  )
}
```

</Imperative>
</ApiTabs>

| Option | Default | Meaning |
|---|---|---|
| `homePosition` | `[0, 0, 4]` | Camera position at start and after `jumpToHome()`. |
| `targetPosition` | `[0, 0, 0]` | The point the camera orbits around. |
| `upVector` | `[0, 1, 0]` | |
| `orbitSpeed` | `0.005` | Radians of orbit per point dragged. |
| `zoomSpeed` | `0.01` | Distance change per unit of scroll delta, relative to the distance to the target. |

`useOrbitGestures` takes `{ pinchSpeed }` as a second argument, the scroll delta per unit of pinch scale change (default `100`).

### Custom gestures

The manipulator's methods work from any thread, so Gesture Handler callbacks can call them on the UI runtime. Coordinates are points from the top-left corner of the view. `useOrbitGestures` builds its gesture with Gesture Handler's `Gesture` builder API, which Gesture Handler 3 marks as deprecated in favor of hooks such as `usePanGesture`.

| Method | Effect |
|---|---|
| `grabBegin(x, y, strafe)` | Starts a drag that orbits, or pans when `strafe` is `true`. |
| `grabUpdate(x, y)`, `grabEnd()` | Moves and ends the drag. |
| `scroll(x, y, delta)` | Zooms; a negative `delta` moves closer to the target. |
| `jumpToHome()` | Returns to the home position. |
| `setViewport(width, height)` | Size in points of the view the input comes from. Needed for panning and the vertical axis. |
| `getLookAt()` | The latest pose, `{ eye, target, up }`, published by the render thread. |

```tsx
manipulator.scroll(100, 100, -20)
manipulator.jumpToHome()
const { eye, target, up } = manipulator.getLookAt()
```

At most 256 commands wait per frame. Consecutive `grabUpdate` calls and `scroll` calls at the same point merge, so only a flood of other commands reaches the limit; those calls throw `FilamentQueueFullError` and change nothing.
