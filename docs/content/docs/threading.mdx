Filament is not thread-safe, so each Engine owns one **render thread** that makes every Filament call. The [API reference](/api) names the thread each method expects with a `@thread` tag.

| `@thread` | Examples | Called from |
|---|---|---|
| `any` | `engine.loadModel()`, `player.play()`, `binding.setTranslation()`, `target.pick()`, `engine.requestFrame()` | Any JS runtime: React Native's, Reanimated's UI runtime or the render runtime. Setters store the latest value and wake the render thread. |
| `render` | `engine.createScene()`, `scene.addModel()`, `transformManager.setTransform()`, `camera.lookAt()` | A worklet on the render thread: through `runOnRenderThread`, a render-thread hook or a frame callback. |
| `RN or UI runtime` | `engine.shutdown()` | React Native's runtime or Reanimated's UI runtime, not the render runtime. |
| `RN runtime` | `runOnRenderThread()`, `workletContext.runAsync()` | React Native's JS runtime. |

Calling a `render` method from another thread throws an error starting with `FilamentThreadError`.

## Running code on the render thread

[`runOnRenderThread(engine, worklet)`](/api/functions/run-on-render-thread) runs a worklet on the Engine's render thread and resolves with its result. Jobs run in the order they were submitted. A job that cannot run because the Engine shut down rejects with an error starting with `FilamentDisposedError`.

```tsx
import { runOnRenderThread } from 'react-native-filament'

const camera = await runOnRenderThread(engine, () => {
  'worklet'
  const created = engine.createCamera()
  created.lookAt([0, 1, 5], [0, 0, 0], [0, 1, 0])
  return created
})
```

[react-native-worklets](https://docs.swmansion.com/react-native-worklets) serializes the values a worklet captures into the render runtime, which is a separate JS runtime: React state and other JS-only values are not visible there. Pass what the worklet needs.

Inside components, use the render-thread hooks. Each `FilamentScene` collects the render-thread work of one React commit and runs it as one job, in submission order.

| Hook | Runs |
|---|---|
| [`useRenderThreadEffect(effect, deps)`](/api/hooks/use-render-thread-effect) | `effect` after commits that change `deps`. A function it returns runs on the render thread before the next run and on unmount. |
| [`useRenderThreadCallback(callback, deps)`](/api/hooks/use-render-thread-callback) | Returns a function that runs `callback` on the render thread and resolves with its result. |
| [`useRenderThreadMemo(factory, deps)`](/api/hooks/use-render-thread-memo) | Returns `factory`'s result, or `undefined` until it arrives. Results of outdated `deps` are dropped. |
| [`useFrameCallback(callback, deps)`](/api/hooks/use-frame-callback) | `callback` at the start of every frame ([Per-frame code](#per-frame-code)). |

A failure in `useRenderThreadEffect` or `useRenderThreadMemo`, or in subscribing a `useFrameCallback`, is thrown to the closest error boundary. The Promise of a `useRenderThreadCallback` function rejects instead.

<ApiTabs>
<Declarative>

```tsx
import { useFilamentContext, useRenderThreadCallback, useRenderThreadEffect, useRenderThreadMemo, type Entity, type Model } from 'react-native-filament'

function Scaled({ entity, model, size }: { entity: Entity; model: Model; size: number }) {
  const { scene, transformManager } = useFilamentContext()

  useRenderThreadEffect(() => {
    'worklet'
    transformManager.setScale(entity, [size, size, size])
    return () => transformManager.setScale(entity, [1, 1, 1])
  }, [transformManager, entity, size])

  const names = useRenderThreadMemo(() => {
    'worklet'
    return model.entities.flatMap((child) => model.getEntityName(child) ?? [])
  }, [model])

  const countEntities = useRenderThreadCallback(() => {
    'worklet'
    return scene.entityCount
  }, [scene])

  return null
}
```

</Declarative>
<Imperative>

```tsx
import { runOnRenderThread } from 'react-native-filament'

await runOnRenderThread(engine, () => {
  'worklet'
  engine.transformManager.setScale(entity, [2, 2, 2])
})

const names = await runOnRenderThread(engine, () => {
  'worklet'
  return model.entities.flatMap((child) => model.getEntityName(child) ?? [])
})
```

## The 1.x worklet hooks

The 1.x hooks still work and run on the same render thread through react-native-worklets.

| 1.x API | Same as |
|---|---|
| [`useWorkletEffect(effect)`](/api/hooks/use-worklet-effect) | `useRenderThreadEffect`, rerun when a value `effect` captures changes |
| [`useWorkletCallback(callback)`](/api/hooks/use-worklet-callback) | `useRenderThreadCallback`, recreated when a value `callback` captures changes |
| [`useWorkletMemo(factory, deps)`](/api/hooks/use-worklet-memo) | `useRenderThreadMemo` |
| `useFilamentContext().workletContext.runAsync(worklet)` | `runOnRenderThread`, queued after the current commit's render-thread work |
| `workletContext.createRunAsync(worklet)` | A function that runs `worklet` with its arguments and resolves with its result |

`useWorkletEffect` and `useWorkletCallback` take no dependency list; their dependencies are the values the worklet captures. A cleanup that `useWorkletEffect` returns runs on the render thread, so it cannot call React state setters or other JS-only functions. [`WorkletContext`](/api/types/worklet-context) is called from React Native's runtime. `apps/shared/src/examples/Worklets.tsx` uses all of them.

## Per-frame code

Three APIs run a worklet on the render thread at the start of every frame, after transform bindings and camera manipulators are applied and before animations, physics and rendering:

- `renderCallback` on [`FilamentView`](/api/components/filament-view);
- the [`useFrameCallback`](/api/hooks/use-frame-callback) hook;
- [`engine.addOnFrameListener`](/api/hybrid-objects/engine), which the other two use.

Each receives a [`FrameInfo`](/api/types/frame-info): `timestampNs` (vsync time in nanoseconds of the platform's monotonic clock), `deltaSeconds` (seconds since the previous rendered frame, 0 on the first frame and after rendering resumes), `elapsedSeconds` (the sum of `deltaSeconds`, so paused time is not counted) and `frameIndex` (the number of frames rendered before this one).

A frame listener returns whether it needs another frame. In `on-demand` mode the Engine keeps rendering while any listener returns `true`. `renderCallback` and `useFrameCallback` always return `true`, so they keep the Engine rendering while they are set. `addOnFrameListener` must be called on the render thread, and `subscription.remove()` works from any thread. An error that a frame callback throws while it runs is only logged natively, in the Xcode console or logcat.

<ApiTabs>
<Declarative>

```tsx
import { useFilamentContext, useFrameCallback, quaternionFromAxisAngle, type Entity } from 'react-native-filament'

function Spin({ entity }: { entity: Entity }) {
  const { transformManager } = useFilamentContext()
  useFrameCallback(({ elapsedSeconds }) => {
    'worklet'
    transformManager.setRotation(entity, quaternionFromAxisAngle([0, 1, 0], elapsedSeconds))
  }, [transformManager, entity])
  return null
}
```

</Declarative>
<Imperative>

```tsx
import { quaternionFromAxisAngle, runOnRenderThread } from 'react-native-filament'

const subscription = await runOnRenderThread(engine, () => {
  'worklet'
  return engine.addOnFrameListener(({ elapsedSeconds }) => {
    engine.transformManager.setRotation(entity, quaternionFromAxisAngle([0, 1, 0], elapsedSeconds))
    return true
  })
})

subscription.remove()
```

</Imperative>
</ApiTabs>

### Each frame

In `continuous` mode (the default) the render thread renders on every display refresh. In `on-demand` mode it renders only when something needs a frame: a write to a binding, a playing animation, a manipulator command, a physics world with awake bodies, a frame listener that returned `true`, an asset upload, a pending `pick()` or `takeSnapshot()`, or `engine.requestFrame()` ([Rendering](/docs/rendering#render-modes)).

Queued jobs (`runOnRenderThread`, the render-thread hooks) run between frames. A job does not request a frame: in `on-demand` mode, call `engine.requestFrame()` after a job that changes what is drawn.

Each frame runs these stages in order:

1. asset uploads;
2. frame info (`deltaSeconds`, `elapsedSeconds`);
3. transform bindings and camera manipulators;
4. frame listeners (`renderCallback`, `useFrameCallback`, `engine.addOnFrameListener`);
5. animation players;
6. physics worlds;
7. skeleton followers;
8. rendering of every view target.

## SharedValues

Reanimated runs worklets on its UI runtime, and the render thread never reads a SharedValue, which would block it on the UI runtime. A listener on the UI runtime writes each new value into a native object the render thread applies at the next frame: [`TransformBinding`](/api/hybrid-objects/transform-binding), [`ValueBinding`](/api/hybrid-objects/value-binding) and [`CameraManipulator`](/api/hybrid-objects/camera-manipulator). Components do this when you pass a SharedValue. [Reanimated](/docs/reanimated) shows how to use the bindings directly.
