An [`Engine`](/api/hybrid-objects/engine) owns a Filament engine, its render thread and its native render loop. Each view renders one scene through one camera into its own surface.

`<FilamentScene>` creates an Engine, a scene and a camera, shows `fallback` until they exist, throws creation failures to the closest error boundary, and shuts its Engine down on unmount. Imperatively, `Filament.createEngine({})` creates an Engine and `await engine.shutdown()` destroys everything it created.

## Sharing an Engine

Every Engine has its own render thread and GPU resources. When a screen shows many views, such as the rows of a list, let them share one Engine. A `FilamentScene` with an `engine` prop creates its own scene and camera, disposes only those, and never shuts the Engine down. `useEngine(backend?)` creates an Engine and shuts it down on unmount.

```tsx
import { FlatList } from 'react-native'
import { Camera, DefaultLight, FilamentScene, FilamentView, Model, useEngine } from 'react-native-filament'

export function Coins() {
  const engine = useEngine()
  if (engine == null) return null
  return (
    <FlatList
      data={[1, 2, 3, 4]}
      renderItem={() => (
        <FilamentScene engine={engine}>
          <FilamentView style={{ height: 180 }}>
            <Camera />
            <DefaultLight />
            <Model source={require('./coin.glb')} transformToUnitCube />
          </FilamentView>
        </FilamentScene>
      )}
    />
  )
}
```

Imperatively, create the Engine once with `Filament.createEngine({})`, create one view target per view with `engine.createViewTarget(view, {})`, and give each target its own scene and camera on the render thread with `target.setScene(engine.createScene())` and `target.setCamera(engine.createCamera())`.

A `ViewTarget` stops rendering when it is garbage collected, so keep the targets you create. Several `<FilamentView>`s inside one `<FilamentScene>` show the same scene through the same camera; for different scenes or cameras on one Engine, use one `<FilamentScene engine={engine}>` per view.

## Backends

| Platform | Backends, preferred first |
|---|---|
| iOS | `metal` |
| Android with Vulkan 1.1 | `vulkan`, `opengl` |
| Android without Vulkan 1.1 | `opengl` (OpenGL ES 3.0) |

`Filament.supportedBackends` lists what the device supports. A new Engine uses the first entry unless you pass `backend`; an unsupported backend rejects with `The backend "<name>" is not supported on this device.` `engine.backend` reports the backend in use and `Filament.filamentVersion` the linked Filament version.

```tsx
import type { ReactNode } from 'react'
import { FilamentScene, useEngine } from 'react-native-filament'

function OpenGlScene({ children }: { children: ReactNode }) {
  return <FilamentScene backend="opengl">{children}</FilamentScene>
}

function SharedOpenGlScene({ children }: { children: ReactNode }) {
  const engine = useEngine('opengl')
  return engine == null ? null : <FilamentScene engine={engine}>{children}</FilamentScene>
}
```

Imperatively, pass `{ backend: 'opengl' }` to `Filament.createEngine()`.

## Render modes

| Mode | Renders |
|---|---|
| `continuous` (default) | On every display refresh while a view is visible. |
| `on-demand` | Only when something needs a frame, then the render thread sleeps. |

In `on-demand` mode these request frames: a write to a `TransformBinding` or `ValueBinding` (including SharedValue-driven props), a playing animation, a camera manipulator command, an automatically stepped physics world with awake bodies, a frame listener that returns `true` (`renderCallback` and `useFrameCallback` always do), an asset upload, a pending `takeSnapshot()` or `pick()`, and `engine.requestFrame()`.

A job on the render thread does not request a frame by itself. When you change the scene in `runOnRenderThread` or a render-thread hook, call `engine.requestFrame()`, which works from any thread.

`renderMode` belongs to the Engine. A `FilamentScene` that sets `renderMode` changes it for every scene of the Engine it uses; without the prop, a scene keeps the Engine's current mode.

```tsx
import type { ReactNode } from 'react'
import { FilamentScene, useFilamentContext, useRenderThreadEffect, type Entity } from 'react-native-filament'

function OnDemandScene({ children }: { children: ReactNode }) {
  return <FilamentScene renderMode="on-demand">{children}</FilamentScene>
}

function Hide({ entity }: { entity: Entity }) {
  const { engine, scene } = useFilamentContext()
  useRenderThreadEffect(() => {
    'worklet'
    scene.removeEntity(entity)
    engine.requestFrame()
    return () => {
      scene.addEntity(entity)
      engine.requestFrame()
    }
  }, [engine, scene, entity])
  return null
}
```

Imperatively, set `engine.renderMode = 'on-demand'` and call `engine.requestFrame()` after changing the scene in `runOnRenderThread`.

## Views

[`FilamentView`](/api/components/filament-view) shows the scene of the closest `FilamentScene` through its camera. It renders a [`NativeFilamentView`](/api/components/native-filament-view) and creates a [`ViewTarget`](/api/hybrid-objects/view-target) for it. It renders its children next to the native view, not on top of it, so place React Native views over it with absolute positioning.

| `FilamentView` prop | Meaning |
|---|---|
| `transparent` | Composites with the views behind it, using a `TextureView` on Android instead of a `SurfaceView`. Default `false`. |
| `clearOptions` | How the view is cleared before each frame: `color` (linear RGBA, default `[0, 0, 0, 0]`), `clear` and `discard`. |
| `targetFrameRate` | Highest rate in frames per second the view renders at. `0`, the default, renders on every display refresh. Frame listeners and native systems still run on every frame of the Engine. |
| `onFirstFrame` | Called once after the view shows its first frame. |
| `renderCallback` | A worklet called on the render thread at the start of every frame ([Threading](/docs/threading#per-frame-code)). |

### View options

Each view has its own rendering options. `FilamentView` takes them as props; imperatively, set them on [`target.view`](/api/hybrid-objects/view) on the render thread. An omitted prop keeps the view's default.

| Option | Type | Default |
|---|---|---|
| `antiAliasing` | `'none'` \| `'fxaa'` | `'fxaa'` |
| `dithering` | `'none'` \| `'temporal'` | `'temporal'` |
| `postProcessing` | `boolean`: tone mapping, bloom, anti-aliasing and the other post-processing passes | `true` |
| `shadowing` | `boolean` | `true` |
| `shadowType` | `'pcf'` \| `'vsm'` \| `'dpcf'` \| `'pcss'` | `'pcf'`, or `'vsm'` on the iOS Simulator |
| `screenSpaceRefraction` | `boolean` | `true` |
| `ambientOcclusionOptions` | [`AmbientOcclusionOptions`](/api/types/ambient-occlusion-options) | disabled |
| `bloomOptions` | [`BloomOptions`](/api/types/bloom-options): bloom and lens flare | disabled |
| `temporalAntiAliasingOptions` | [`TemporalAntiAliasingOptions`](/api/types/temporal-anti-aliasing-options) | disabled |
| `dynamicResolutionOptions` | [`DynamicResolutionOptions`](/api/types/dynamic-resolution-options): scales the resolution with GPU load | disabled |

Each imperative `set*Options` call replaces every option of its group; omitted fields take Filament's defaults.

## Shutting down

`engine.shutdown()` destroys every native resource of the Engine and resolves once the render thread has exited. Every call returns a Promise that settles at the same time, so calling it twice is safe. Call it from the React Native runtime or Reanimated's UI runtime, not inside a render-thread worklet. `engine.dispose()` starts the same shutdown without returning a Promise.

After shutdown, pending `runOnRenderThread` jobs reject with an error starting with `FilamentDisposedError`, loads and `createViewTarget()` calls still in flight reject with an error saying the Engine was shut down, and `requestFrame()` does nothing.
