## Counting live resources

`engine.getDebugStats().liveResources` counts, by kind, the native resources the Engine still holds, such as `{ Model: 1, Scene: 2 }`. It works from any thread. The kinds are `Camera`, `CollisionShape`, `IndirectLight`, `Light`, `Material`, `MaterialInstance`, `Model`, `PhysicsWorld`, `Recorder`, `Renderable`, `RigidBody`, `Scene`, `Skybox`, `Texture` and `ViewTarget`. A kind with no live resources is left out, and after `engine.shutdown()` the object is empty. Bindings, manipulators, model instances, animators and animation players are not counted.

To find a leak, read the stats, mount and unmount the screen or run the code under test, then read them again. Anything still counted was not disposed ([Architecture](/docs/architecture#lifetime)). `dispose()` destroys the native object in a render-thread job, so a count lags behind until that job runs; once a later `runOnRenderThread()` call resolves, the stats are up to date.

```tsx
import { Button } from 'react-native'
import { useFilamentContext } from 'react-native-filament'

function DebugStatsButton() {
  const { engine } = useFilamentContext()
  return <Button title="Log live resources" onPress={() => console.log(engine.getDebugStats().liveResources)} />
}
```

## Visualizing bounds with `<DebugBox />`

`<DebugBox />` draws the wireframe edges of a box. Inside a `<Model>` it defaults to the model's bounding box and follows the model as it moves; elsewhere, pass `halfExtent` and optionally `center`. `color` is linear RGBA and defaults to green, and the box accepts `translate`, `rotate` and `scale`. Imperatively, `engine.createDebugBox(options)` returns a `Renderable` on the render thread; parent it to the model's root entity with `transformManager.setParent()` to make it follow.

```tsx
import { DebugBox, Model } from 'react-native-filament'

function DroneWithBounds() {
  return (
    <>
      <Model source={require('./drone.glb')} transformToUnitCube>
        <DebugBox color={[1, 1, 0, 1]} />
      </Model>
      <DebugBox halfExtent={[0.5, 0.5, 0.5]} translate={[2, 0, 0]} />
    </>
  )
}
```

## Measuring the frame rate

Every frame listener receives a `FrameInfo`. Summing `deltaSeconds` gives the render thread's frame rate. A listener that returns `false` requests no frames after the one its registration renders, so it does not keep an `on-demand` Engine awake.

```tsx
import { useState } from 'react'
import { Text } from 'react-native'
import { scheduleOnRN } from 'react-native-worklets'
import { useFilamentContext, useRenderThreadEffect } from 'react-native-filament'

function FpsCounter() {
  const { engine } = useFilamentContext()
  const [fps, setFps] = useState(0)
  useRenderThreadEffect(() => {
    'worklet'
    let frames = 0
    let seconds = 0
    const subscription = engine.addOnFrameListener((frame) => {
      frames++
      seconds += frame.deltaSeconds
      if (seconds >= 1) {
        scheduleOnRN(setFps, Math.round(frames / seconds))
        frames = 0
        seconds = 0
      }
      return false
    })
    return () => subscription.remove()
  }, [engine, setFps])
  return <Text>{fps} fps</Text>
}
```

## Errors

Most native failures throw, or reject a Promise, with an error whose message starts with the error's name, such as `FilamentDisposedError: ...`. Components and hooks rethrow asynchronous failures during the next render, so the closest React error boundary receives them. An error that a frame callback throws while it runs is only logged natively, in the Xcode console or logcat.

| Error | Cause |
|---|---|
| `FilamentDisposedError` | A method was called on a disposed object, or the Engine shut down before a `runOnRenderThread` job ran. Loads and `createViewTarget()` calls that shutdown cancels reject with an error saying the Engine was shut down instead. |
| `FilamentThreadError` | A `@thread render` method was called outside the Engine's render thread. Move the call into `runOnRenderThread()` or a render-thread hook. |
| `FilamentInvalidEntityError` | The entity has no component of the required kind in this Engine, for example `scene.addEntity()` with a camera's entity. |
| `FilamentEngineMismatchError` | An object from one Engine was passed to another Engine's object. |
| `FilamentAssetError` | A source is not in the expected format, for example a model that is not a self-contained `.glb`, a material compiled for another Filament version, a texture that is not PNG, JPEG or KTX2, or a cubemap that is not KTX1. |
| `FilamentBusyError` | `recorder.record()` was called while another recording runs. |
| `FilamentRecorderError` | The video encoder failed, for example H.264 cannot encode the requested size on this device. |
| `FilamentQueueFullError` | Too many camera manipulator commands were queued before the render thread applied them. |

## Performance tips

- **Use one Engine per screen.** Each Engine has its own render thread and GPU resources. For many views on one screen, share one Engine ([Rendering](/docs/rendering#sharing-an-engine)).
- **Dispose what you create**, and check `engine.getDebugStats()` for leftovers.
- **Instance repeated models.** Load a model once with `instanceCount` instead of several times ([Instancing](/docs/instancing)).
- **Keep lights cheap.** Give point and spot lights a small `falloffRadius` ([Lights](/docs/lights)).
- **Turn off what you do not need.** View options such as `bloomOptions`, `ambientOcclusionOptions`, `postProcessing` and `shadowing` cost GPU time; `targetFrameRate` caps how often a view renders ([Rendering](/docs/rendering#views)).
- **Render only when something changes.** With `renderMode="on-demand"`, the render loop stops while nothing needs a frame, which suits a mostly still scene such as a product viewer ([Rendering](/docs/rendering#render-modes)).
- **Choose the backend.** On Android, pass `backend="opengl"` to `<FilamentScene>`, `useEngine('opengl')` or `Filament.createEngine({ backend: 'opengl' })` to compare it with Vulkan ([Rendering](/docs/rendering#backends)).
